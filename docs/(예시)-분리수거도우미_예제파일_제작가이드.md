# 분리수거 도우미 — 예제 파일 제작 가이드

> **6차시 PRIMM 수업용 교사 사전 제작 자료**
> 대상 : 초등 5학년 3인 1팀 · 도구 : 엔트리 + 마이크로비트 v2 + 웹캠
> 본 문서는 『만들면서 배우는 AI 발명 프로젝트』 6차시 커리큘럼의 부속 자료입니다.

---

## 왜 예제를 미리 만들어야 하는가

PRIMM 수업은 **이미 작동하는 코드**에서 출발합니다. 학생은 백지에서 코딩하지 않고, 남이 짠 코드를 예측하고 돌려보고 뜯어보며 원리를 익힌 뒤 자기 것으로 고칩니다.

따라서 **예제 파일이 없으면 이 수업은 성립하지 않습니다.** 그리고 예제는 세 가지 조건을 지켜야 합니다.

1. **10줄을 넘기지 않는다** — 크면 어디를 봐야 할지 모릅니다.
2. **한 파일에 한 가지 원리만 담는다** — 두 가지가 섞이면 무엇 때문에 달라졌는지 알 수 없습니다.
3. **바꿀 지점이 눈에 띄어야 한다** — 숫자와 순서가 드러나 있어야 합니다.

---

## 파일 목록 — 6종 8개

| 종 | 파일명 | 차시 | PRIMM | 목적 |
|---|---|---|---|---|
| 1 | `00_완성예제_분리수거도우미` | 1 | P·R | 만들 것의 전체 모습 |
| 2 | `CV-1_분류만보기` | 2 | I | 분류의 기본 흐름 |
| 3 | `CV-2_신뢰도보기` | 2 | I | AI는 확신도로 말한다 |
| 4 | `CV-3_순서A` / `CV-3_순서B` | 2 | I | **조건 순서** (두 개 필요) |
| 5 | `PC-1_버튼과LED` / `PC-1_지우기위로` | 3 | I | **블록 순서** (두 개 필요) |
| 6 | `PC-2_밝기센서` | 3 | I | 센서 입력 |

> 4번과 5번은 **반드시 두 파일씩** 만드세요. 블록은 같고 순서만 다른 쌍을 나란히 놓고 비교하는 것이 이 수업의 핵심 장치입니다.

# 1부 · 공통 준비

두 가지를 먼저 만들어야 8개 파일을 만들 수 있습니다.

---

## 1.1 학습 모델 — 「분리수거 4분류」

모든 CV 예제와 완성 예제가 이 모델 하나를 씁니다.

### 클래스 구성

| 클래스 | 이름 | 무엇을 찍나 | 장수 |
|---|---|---|---|
| ① | **플라스틱** | 페트병, 플라스틱 컵, 요구르트병 | 40장 |
| ② | **종이** | 우유팩, 종이컵, 신문지, 상자 조각 | 40장 |
| ③ | **캔** | 음료 캔, 통조림 캔 | 40장 |
| ④ | **모르겠음** | 빈 배경, 손, 필통, 신발, 책 | 4V0장 |

### 촬영 사양 — 여기가 중요합니다

이 모델은 **일부러 조금만 튼튼하게** 만듭니다. 완벽하면 5차시 테스트에서 실패가 안 나오고, 실패가 없으면 6차시에 고칠 게 없습니다.

| 항목 | 이렇게 |
|---|---|
| 촬영 장소 | **2곳** (교실 앞 흰 벽 / 교실 뒤) — 3곳 이상은 너무 튼튼해집니다 |
| 거리 | 30cm 고정 |
| 각도 | 정면 위주, 약간의 좌우 |
| 조명 | 형광등만 (창가 자연광은 **제외**) |
| 드는 사람 | 교사 한 명 |

> **의도적 약점** — 창가 조명과 다양한 사람의 손을 뺐습니다. 5차시 테스트 T5(창가 이동), T7(다른 사람이 들기)에서 이 모델은 무너집니다. 그것이 6차시 개선의 재료입니다.

### '모르겠음' 클래스 촬영 요령

가장 소홀히 하기 쉬운 클래스입니다. 여기가 부실하면 AI가 신발도 플라스틱이라고 말합니다.

```
  빈 배경만          10장
  손만 보이기        10장
  엉뚱한 물건        10장   (필통, 책, 지우개)
  물건이 반쯤 나감    10장
```

## 1.2 마이크로비트 LED 함수 4종

마이크로비트 LED는 5×5 = 25개입니다. 매번 25개를 좌표로 켜는 블록을 학생에게 보여주면 예제가 순식간에 50줄이 됩니다.

그래서 **교사가 `내 블록`(함수)으로 미리 감싸 둡니다.** 학생은 `[하트 보여주기]` 한 줄만 씁니다.

> **PRIMM 관점의 설계 의도** — 배관은 미리 깔아두고, 학생은 **의미 있는 부분만** 조작하게 합니다. 함수 내부는 3차시에 궁금해하는 학생에게만 열어 보여주세요.

### 함수 ① 하트 보여주기 — 플라스틱

```
 . ■ . ■ .        켤 좌표 (x, y)
 ■ ■ ■ ■ ■        (1,0) (3,0)
 ■ ■ ■ ■ ■        (0,1) (1,1) (2,1) (3,1) (4,1)
 . ■ ■ ■ .        (0,2) (1,2) (2,2) (3,2) (4,2)
 . . ■ . .        (1,3) (2,3) (3,3)
                  (2,4)
```

### 함수 ② 네모 보여주기 — 종이

```
 ■ ■ ■ ■ ■        (0,0) (1,0) (2,0) (3,0) (4,0)
 ■ . . . ■        (0,1) (4,1)
 ■ . . . ■        (0,2) (4,2)
 ■ . . . ■        (0,3) (4,3)
 ■ ■ ■ ■ ■        (0,4) (1,4) (2,4) (3,4) (4,4)
```

### 함수 ③ 세모 보여주기 — 캔

```
 . . ■ . .        (2,0)
 . ■ . ■ .        (1,1) (3,1)
 ■ ■ ■ ■ ■        (0,2) (1,2) (2,2) (3,2) (4,2)
 . . . . .
 . . . . .
```

### 함수 ④ 엑스 보여주기 — 모르겠음

```
 ■ . . . ■        (0,0) (4,0)
 . ■ . ■ .        (1,1) (3,1)
 . . ■ . .        (2,2)
 . ■ . ■ .        (1,3) (3,3)
 ■ . . . ■        (0,4) (4,4)
```

### 함수 내부 구성 (하트 예시)

```
[ 함수 정의 : 하트 보여주기 ]
   [ 마이크로비트 모든 LED 끄기 ]
   [ 마이크로비트 LED (1) (0) 켜기 ]
   [ 마이크로비트 LED (3) (0) 켜기 ]
   [ 마이크로비트 LED (0) (1) 켜기 ]
   [ 마이크로비트 LED (1) (1) 켜기 ]
   ... (좌표표대로 계속)
   [ 마이크로비트 LED (2) (4) 켜기 ]
```

> **제작 요령** — 하트를 먼저 완성한 뒤 함수를 복제해 좌표만 바꾸면 나머지 3개는 금방 만듭니다.

> **엔트리 버전 확인** — 아이콘을 통째로 출력하는 블록(예: `LED에 (하트) 출력하기`)이 있는 버전이라면 그것을 쓰는 편이 훨씬 간단합니다. 사전 점검 때 확인하고, 있으면 함수 4개를 만들 필요가 없습니다. 없을 경우를 대비한 것이 위 좌표표입니다.

# 예제 1 — `00_완성예제_분리수거도우미`

> **1차시 · PRIMM P(예측) · R(실행)**
> 학생이 이 수업에서 만들 것의 전체 모습을 처음 만나는 파일

## 목적

작동하는 완성품을 보여줍니다. **코드를 이해시키는 것이 목적이 아닙니다.** "우리도 이런 걸 만드는구나"를 심고, 예측이 빗나가는 경험을 주는 것이 목적입니다.

## 오브젝트 구성

| 오브젝트 | 역할 |
|---|---|
| **안내 로봇** (엔트리봇) | 판단 결과를 말풍선으로 말함 |
| **배경** | 단색 (흰색 또는 연회색) |

## 블록 구성

```
[ 시작하기 버튼을 클릭했을 때 ]
  [ 마이크로비트 모든 LED 끄기 ]
  [ "분리수거 도우미를 시작합니다" 를 (2) 초 동안 말하기 ]

  [ 계속 반복하기 ]
      [ 학습한 모델로 분류하기 ]

      [ 만약  (분류 결과) = (플라스틱)  이라면 ]
          [ "파란 통이에요" 라고 말하기 ]
          [ 하트 보여주기 ]
          [ 마이크로비트 (도) 음을 (0.5) 초 연주하기 ]

      [ 아니면 만약  (분류 결과) = (종이)  이라면 ]
          [ "초록 통이에요" 라고 말하기 ]
          [ 네모 보여주기 ]
          [ 마이크로비트 (미) 음을 (0.5) 초 연주하기 ]

      [ 아니면 만약  (분류 결과) = (캔)  이라면 ]
          [ "회색 통이에요" 라고 말하기 ]
          [ 세모 보여주기 ]
          [ 마이크로비트 (솔) 음을 (0.5) 초 연주하기 ]

      [ 아니면 ]
          [ "잘 모르겠어요. 다시 보여주세요" 라고 말하기 ]
          [ 엑스 보여주기 ]

      [ (1) 초 기다리기 ]
      [ 마이크로비트 모든 LED 끄기 ]
```

## 학생용 예측 질문 (실행 전에 각자 작성)

| # | 질문 |
|---|---|
| P1 | 페트병을 보여주면 어떻게 될까? |
| P2 | 연필을 보여주면 어떻게 될까? |
| P3 | 아무것도 안 보여주면 어떻게 될까? |
| P4 | `1초`를 `5초`로 바꾸면 어떻게 달라질까? |
| P5 | 마이크로비트에는 무엇이 나타날까? |

## 실행 단계에서 일부러 시킬 것

예측에 없던 것을 보여주게 하세요. 여기서 아이들 눈이 커집니다.

- 신발 · 손 · 얼굴
- 페트병을 반쯤 가리고
- 창가로 가져가서
- 물건을 아주 빠르게 바꿔가며

> **교사 유의** — 이 파일의 코드를 1차시에 **설명하지 마세요.** "저건 뭐예요?"라는 질문이 나오면 "2차시에 하나씩 뜯어볼 거야"로 넘깁니다. 궁금증을 남기는 것이 이 파일의 역할입니다.

# 예제 2 — `CV-1_분류만보기`

> **2차시 · PRIMM I(조사) · 실험 A**
> 컴퓨터 비전의 최소 골격

## 목적

분류의 기본 흐름 — **보고 → 판단하고 → 말하고 → 쉰다** — 를 4줄로 보여줍니다. 마이크로비트는 붙이지 않습니다.

## 오브젝트 구성

| 오브젝트 | 역할 |
|---|---|
| **안내 로봇** | 분류 결과를 말함 |

## 블록 구성

```
[ 시작하기 버튼을 클릭했을 때 ]
  [ 계속 반복하기 ]
      [ 학습한 모델로 분류하기 ]
      [ ( ("결과: ") 와 (분류 결과) 를 합치기 ) 라고 말하기 ]
      [ (0.5) 초 기다리기 ]
```

**딱 4줄입니다.** 더 넣지 마세요.

## 조작 지점 — 실험 A

학생이 바꿀 곳은 **`0.5` 하나뿐**입니다.

| # | 바꿀 것 | 예측 질문 | 나오는 결론 |
|---|---|---|---|
| A1 | `0.5` → `3` | 어떻게 달라질까? | 느려짐 · 답답함 |
| A2 | `0.5` → `0.05` | 어떻게 달라질까? | 정신없이 깜빡임 |
| A3 | (안 바꿈) 웹캠 가리기 | 뭐라고 말할까? | 모르겠음 또는 엉뚱한 답 |
| A4 | (안 바꿈) 아주 멀리 두기 | 맞힐까? | 자주 틀림 |

> **핵심 발문 (A2 이후)** — "왜 기다리는 시간이 필요할까요?"
> 사람이 읽을 시간이 필요하고, 컴퓨터도 쉴 틈이 필요하다는 답이 나오면 충분합니다.

## 제작 시 주의

- 말하기는 `~라고 말하기`(계속 유지)를 씁니다. `~초 동안 말하기`를 쓰면 반복문이 그만큼 멈춰서 실험 A1·A2의 차이가 흐려집니다.
- 배경과 오브젝트를 단순하게 두세요. 시선이 코드로 가야 합니다.

# 예제 3 — `CV-2_신뢰도보기`

> **2차시 · PRIMM I(조사) · 실험 B**
> AI는 "확실하다"고 말하지 않는다

## 목적

AI가 **확신도(신뢰도)** 로 답한다는 것, 그리고 **주어진 보기 중에서만 고른다**는 것을 드러냅니다. '모르겠음' 클래스가 왜 필요한지가 여기서 나옵니다.

## 블록 구성

```
[ 시작하기 버튼을 클릭했을 때 ]
  [ 계속 반복하기 ]
      [ 학습한 모델로 분류하기 ]
      [ ( (분류 결과) 와 ( ("  플라스틱 확신도 ") 와 (플라스틱 에 대한 신뢰도) 를 합치기 ) 를 합치기 ) 라고 말하기 ]
      [ (0.5) 초 기다리기 ]
```

말하기 블록이 길어 보이지만 화면에는 이렇게 나옵니다.

```
   플라스틱   플라스틱 확신도 0.87
   종이      플라스틱 확신도 0.04
   모르겠음   플라스틱 확신도 0.11
```

## 조작 지점 — 실험 B

이 파일에서는 **코드를 바꾸지 않습니다.** 대신 카메라 앞의 상황을 바꿉니다.

| # | 해볼 것 | 예측 | 관찰할 것 |
|---|---|---|---|
| B1 | 페트병 정면 | 확신도 몇 %? | 대개 0.8 이상 |
| B2 | 페트병 반쯤 가리기 | 올라갈까 내려갈까? | 내려감 |
| B3 | 아무것도 없음 | 확신도가 0이 될까? | **0이 아님** |
| B4 | **연필 보여주기** | 확신도가 0이 될까? | **0이 아님** |

> **핵심 발문 (B4 이후)** — "연필인데도 플라스틱 확신도가 0이 아니네요. AI는 왜 '이건 모르겠어요'라고 말하지 못할까요?"
>
> **끌어낼 답** — AI는 우리가 준 보기(플라스틱·종이·캔·모르겠음) 중에서만 고릅니다. 보기에 없으면 그중 제일 비슷한 걸 고를 뿐입니다. 그래서 **'모르겠음'이라는 보기를 우리가 직접 만들어 줘야 합니다.**

이 결론이 같은 차시 활동 2(클래스 확정)로 바로 이어집니다.

## 제작 시 주의

- 신뢰도 블록의 정확한 이름과 값 형식(0~1 또는 0~100)은 **엔트리 버전에 따라 다릅니다.** 사전 점검에서 확인하고, 값이 0~100으로 나오면 실험 B의 관찰 칸을 %로 바꿔 인쇄하세요.
- 신뢰도는 **플라스틱 하나만** 표시합니다. 네 개를 다 띄우면 화면이 복잡해져 관찰이 흐려집니다.

# 예제 4 — `CV-3_순서A` / `CV-3_순서B`

> **2차시 · PRIMM I(조사) · 실험 C**
> **이 수업에서 가장 중요한 파일 쌍입니다**

## 목적

**블록이 완전히 같고 순서만 다른** 두 파일을 비교합니다. `만약 ~ 아니면`이 위에서부터 하나만 실행하고 나머지를 건너뛴다는 것을 발견하게 합니다.

## `CV-3_순서A` — 올바른 순서


# 예제 5 — `PC-1_버튼과LED` / `PC-1_지우기위로`

> **3차시 · PRIMM I(조사) · 실험 D · E**
> 피지컬 컴퓨팅 입력–판단–출력의 최소 형태

## 목적

마이크로비트가 **버튼(입력) → 판단 → LED·소리(출력)** 로 동작함을 보여주고, **블록 순서가 결과를 바꾼다**는 것을 한 번 더 확인시킵니다.

## `PC-1_버튼과LED` — 올바른 순서

```
[ 시작하기 버튼을 클릭했을 때 ]
  [ 마이크로비트 모든 LED 끄기 ]

  [ 계속 반복하기 ]
      [ 만약  (마이크로비트 버튼 A 를 눌렀는가?)  이라면 ]
          [ 하트 보여주기 ]
          [ 마이크로비트 (도) 음을 (0.5) 초 연주하기 ]
          [ (1) 초 기다리기 ]
          [ 마이크로비트 모든 LED 끄기 ]
```

## `PC-1_지우기위로` — 끄기를 반복문 맨 앞으로

```
[ 시작하기 버튼을 클릭했을 때 ]

  [ 계속 반복하기 ]
      [ 마이크로비트 모든 LED 끄기 ]        ◀── 맨 위로 올라옴
      [ 만약  (마이크로비트 버튼 A 를 눌렀는가?)  이라면 ]
          [ 하트 보여주기 ]
          [ 마이크로비트 (도) 음을 (0.5) 초 연주하기 ]
```

## 실험 D — 값 바꾸기 (`PC-1_버튼과LED`에서)

| # | 바꿀 것 | 예측 질문 | 결론 |
|---|---|---|---|
| D1 | `하트 보여주기` → `네모 보여주기` | 무엇이 나올까? | 함수 이름이 곧 모양 |
| D2 | `(도)` → `(솔)` | 어떻게 달라질까? | 음이 높아짐 |
| D3 | `0.5초` → `2초` | 어떻게 달라질까? | **버튼을 빨리 눌러도 안 받음** |
| D4 | `버튼 A` → `버튼 B` | 어느 버튼이 작동할까? | B만 작동 |

> **핵심 발문 (D3 이후)** — "소리가 나는 동안 버튼을 눌렀는데 왜 반응이 없죠?"
> **끌어낼 답** — 프로그램은 한 번에 한 가지만 합니다. 앞줄이 끝나야 다음 줄로 갑니다.

## 실험 E — 순서 바꾸기 (두 파일 비교)

```
 ┌─────────────────────────────────────────────────────┐
 │ 1. 두 코드를 나란히 띄운다                             │
 │ 2. "버튼을 누르면 하트가 보일까요?"  → 각자 예측         │
 │ 3. 버튼과LED 실행 → 하트가 1초간 잘 보임                │
 │ 4. 지우기위로 실행 → 깜빡이거나 거의 안 보임             │
 └─────────────────────────────────────────────────────┘
```

> **발문** — "블록은 똑같은데 왜 안 보일까요?"
> **끌어낼 답** — 켜자마자 지워지기 때문입니다.

```
   ┌────────────────────────────────────────┐
   │   켜기  →  잠깐 보여주기  →  지우기        │
   │                                        │
   │   지우기는 항상 마지막에.                  │
   └────────────────────────────────────────┘
```

이 결론이 5차시 통합 코드(`우리 코드 v0.2`)의 마지막 두 줄 순서를 결정합니다.

## 제작 시 주의

- **함수 4종(1.2절)이 먼저 만들어져 있어야** 합니다. 두 파일 모두 `하트 보여주기` 함수를 씁니다.
- `PC-1_지우기위로`에는 시작 부분의 `모든 LED 끄기`를 넣지 마세요. 반복문 안의 끄기 하나만 남겨야 순서 차이가 선명합니다.
- 마이크로비트 v1에는 스피커가 없습니다. v1을 쓴다면 소리 블록을 빼고 LED만으로 진행하세요.

# 예제 6 — `PC-2_밝기센서`

> **3차시 · PRIMM I(조사) · 실험 F**
> 센서 입력과 대기 시간

## 목적

버튼 말고도 **센서라는 입력**이 있다는 것을 보여주고, 대기 시간 블록이 왜 필요한지를 한 번 더 확인시킵니다.

## 블록 구성

```
[ 시작하기 버튼을 클릭했을 때 ]
  [ 계속 반복하기 ]
      [ ( ("밝기: ") 와 (마이크로비트 밝기 값) 를 합치기 ) 라고 말하기 ]
      [ (0.2) 초 기다리기 ]
```

**3줄입니다.**

## 조작 지점 — 실험 F

| # | 해볼 것 | 예측 | 관찰 |
|---|---|---|---|
| F1 | 보드를 손으로 덮기 | 값이 오를까 내릴까? | 내려감 (0에 가까움) |
| F2 | 창가로 가져가기 | | 올라감 |
| F3 | 스탠드를 바로 비추기 | 최대값은 얼마? | |
| F4 | **`0.2초 기다리기`를 삭제** | 더 빨라질까? | **오히려 느려짐 · 버벅임** |

이 결론은 5차시에서 웹캠 AI와 마이크로비트를 동시에 돌릴 때 버벅임이 생기면 **학생이 스스로 원인을 짚게** 해줍니다.

## 제작 시 주의

- 마이크로비트를 USB로 연결한 상태여야 밝기 값이 읽힙니다.
- 밝기 값의 범위(0~255 또는 0~9)는 엔트리 버전에 따라 다릅니다. 사전 점검에서 실제 범위를 확인해 두세요.

# 3부 · 제작 순서와 점검

## 3.1 만드는 순서

앞의 것이 뒤의 것의 재료가 되므로 **이 순서를 지키세요.**

```
 1단계   학습 모델 「분리수거 4분류」 만들기        (1.1절)   약 40분
           │
           ▼
 2단계   LED 함수 4종 만들기                     (1.2절)   약 30분
           │
           ├──────────────┬──────────────┐
           ▼              ▼              ▼
 3단계   CV-1  ─▶ CV-2   PC-1 ─▶ PC-1′   PC-2      각 5~10분
           │                                    복제 후 수정하면 빠름
           ▼
 4단계   CV-3_순서A  ─▶  복제  ─▶  CV-3_순서B          약 15분
           │
           ▼
 5단계   00_완성예제  (CV-3_순서A + 함수 4종 결합)       약 20분
```

> **요령** — CV-1을 만든 뒤 복제해서 CV-2를 만들고, CV-2를 복제해 CV-3_순서A를 만듭니다. 순서B는 순서A를 복제해 블록 위치만 옮깁니다. 처음부터 만들지 마세요.

## 3.2 사전 점검 체크리스트

**수업 2주 전, 실제로 쓸 PC에서** 확인하세요.

### 기본 환경
- [ ] 브라우저에서 웹캠 권한이 허용되는가
- [ ] 엔트리 하드웨어 연결 프로그램이 설치되어 있는가
- [ ] 마이크로비트 펌웨어(.hex)가 업로드되어 있는가
- [ ] USB 케이블이 **데이터 전송용**인가 (충전 전용이면 연결 안 됨)

### 블록 이름 확인 — 버전마다 다릅니다
- [ ] 신뢰도 블록의 정확한 이름은? → `_______________`
- [ ] 신뢰도 값의 범위는? → ☐ 0~1  ☐ 0~100
- [ ] LED 아이콘 출력 블록이 있는가? → ☐ 있음(함수 불필요)  ☐ 없음
- [ ] 밝기 값의 범위는? → `_______________`
- [ ] 음 연주 블록이 v2에서 작동하는가

### 동시 실행 부하 — 가장 중요
- [ ] 웹캠 분류 + 마이크로비트 출력을 **동시에** 5분간 돌려보았는가
- [ ] 버벅임이 있는가 → 있다면 대기 시간을 얼마로 올려야 하는가 `______`
- [ ] 연결이 끊기는가 → 끊긴다면 **대안 계획**을 준비했는가

> **대안 계획** — 동시 실행이 불안정하면 5차시를 화면 출력만으로 진행하고, 마이크로비트는 교사 시범용 1세트로 운영합니다. 이 경우 3차시(PC-1, PC-2)는 그대로 진행할 수 있으므로 피지컬 컴퓨팅 학습은 유지됩니다.

### 모델 성능 확인 — 일부러 완벽하지 않아야 함
- [ ] 학습한 자리에서 4개 클래스를 잘 맞히는가 (여기는 잘 되어야 함)
- [ ] **창가로 옮기면 틀리는가** (틀려야 정상 — 6차시 재료)
- [ ] **다른 사람이 들면 틀리는가** (틀려야 정상)
- [ ] 신발·필통을 '모르겠음'으로 처리하는가

## 3.3 파일 배포 방법

| 차시 | 학생에게 여는 파일 | 비고 |
|---|---|---|
| 1 | `00_완성예제` | 코드 설명 금지 |
| 2 | `CV-1` → `CV-2` → `CV-3_순서A` + `CV-3_순서B` | 순서대로, 한 번에 하나만 |
| 3 | `PC-1_버튼과LED` + `PC-1_지우기위로` → `PC-2` | |

| 5 | 4차시 파일에 이어서 | 함수 4종 불러오기 |
| 6 | 5차시 파일에 이어서 | 회전마다 복제 저장 |

> **4차시 이후 저장 규칙** — 고치기 전에 **반드시 복제해서 저장**하게 하세요. `우리코드_v0.1`, `v0.2`, `v0.3`. 6차시 개선에서 "되돌리기"가 필요할 때 이 백업이 없으면 처음부터 다시 만들어야 합니다.
