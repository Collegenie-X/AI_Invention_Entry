# ⚡ 틴스파크AI를 한 줄로 말하면

> **답은 다 알려 주고, 마지막에 "너라면?" 하고 한 번 더 물어보는 기획 코치**

### 작동 방식 3단계

1. **🤖 답을 끝까지 준다** — 아끼지 않고 다 알려 줘요
2. **🙋 질문을 하나만 한다** — "너라면 누구를 위해 만들래?"
3. **📝 내 대답이 설계도에 쌓인다** — 내 말로 된 기획서 완성!

# 📚 수학 문제로 비유하면

- 👍 생각하는 힘이 생긴다
- 👎 막히면 하루 종일 제자리
- = **칸미고 같은 AI 튜터**

### ⚡ 틴스파크AI
- 풀이를 **다 보여 준 뒤** "이 공식은 왜 썼을까?"
- 👍 빠르면서 생각하는 힘도 생긴다
- = **답 + 생각 둘 다!**

# 🏠 코드보다 먼저, 설계도

집 짓기로 생각해 볼까요?

```
          🏠 완성된 집 (= 앱)
              ▲
      🧱 벽돌 쌓기 (= 코딩)     ← AI가 금방 해 줘요
              ▲
      📐 설계도 (= 기획)        ← 이건 내가 정해야 해요!
```

- 벽돌 쌓기(코딩)는 이제 AI가 몇 분이면 해요.
- 하지만 **어떤 집을, 누구를 위해, 왜** 지을지는 AI가 대신 못 정해요.
- 틴스파크AI는 이 **설계도**를 같이 만들어 줘요.

---

# 📐 설계도는 딱 세 칸

서연이의 급식 앱으로 채워 볼게요.

```
📐 급식 알레르기 앱 설계도
│
├── 🧭 기획 (누구의 무엇을, 왜?)
│     └─ 견과류 알레르기가 있는 민지가
│        매일 급식표를 일일이 찾는 불편을 없앤다
│
├── 🔀 알고리즘 (어떤 순서와 규칙으로?)
│     └─ 오늘 메뉴 들어옴 → 민지 알레르기와 비교 → 겹치면 🔴 빨간색
│
└── 🏗 전체 구조 (무엇이 무엇과 이어지나?)
      └─ 급식표 데이터 ↔ 내 알레르기 정보 ↔ 알림 화면
```

> 📖 **알고리즘**이란? 일이 처리되는 **순서와 규칙**이에요. 라면 끓이는 순서도 알고리즘!

# ① 🙋 되묻기 — 답 끝에 붙는 질문 하나

```
┌─ 🤖 AI의 답 ──────────────────────────
│  예약 기능, 남은 빵 할인 알림, 단골 쿠폰…
│  방법을 끝까지 다 알려 줌 (100%)
│
└─ 🙋 되묻기 (딱 1개) ──────────────────
   "단골과 처음 온 손님 중,
    누구의 하루를 먼저 바꾸고 싶어?"
```

### 되묻기의 규칙 3가지

- ✅ 답을 **먼저 다** 준다 (답을 인질로 잡지 않아요)
- ✅ 질문은 **딱 하나만**
- ✅ 대답 안 해도 괜찮아요 (억지로 묻지 않아요)

→ 이 질문 하나로 **"누구를 위한 앱인지"** 스스로 정하게 돼요!

---

# ② 🎚 질문의 열림 — 라디오 볼륨처럼

질문은 너무 좁아도, 너무 넓어도 안 돼요. **가운데가 제일 잘 들려요!**

```
 닫힘 ◀───────────────────────────────────▶ 열림

  O1        O2        O3 ⭐       O4         O5
  ⌨️        👨‍💻        🛠          🏛         📚
받아쓰기    코더      엔지니어    아키텍트    백과사전

  ▲                                           ▲
  너무 닫으면                            너무 열면
  "내 판단만 남음"                  "나랑 상관없는 답"
```

> 앱에서는 답마다 `🔎 O3` 표시가 붙어서
> **내 질문이 지금 몇 번 칸인지** 바로 알 수 있어요.

---

# 🎚 같은 빵집, 5가지 질문 방법

| 단계 | 이렇게 물으면 | AI가 변하는 모습 | 결과 |
| --- | --- | --- | --- |
| **O1** 지시 | "빵 남으면 알림 코드 짜줘" | ⌨️ 받아쓰기만 함 | 😐 시킨 것만 |
| **O2** 좁은 질문 | "알림 함수 어떻게 짜?" | 👨‍💻 코드만 짬 | 😐 설계가 틀려도 그대로 |
| **O3** 조건 있는 질문 ⭐ | "빵을 덜 버리고 싶어. 사장님 혼자, 서버 없이. 방법은?" | 🛠 **맞춤 설계 + 이유** | 😄 **최고!** |
| **O4** 대안 질문 | "다른 방법 두 개만 더. 뭘 포기해야 해?" | 🏛 선택지 비교 | 🙂 시간이 좀 걸림 |
| **O5** 맨 열린 질문 | "빵집 앱 어떻게 만들어?" | 📚 교과서 같은 설명 | 😐 누구에게나 같은 답 |

> 🎯 **목표: O3로 묻기** = 목표 + 조건 + 기준을 넣어서 방법을 묻기

# ③ 🧩 여섯 축 — 질문에 한 겹 더 붙이기

질문에 **딱 하나만** 더 붙여도 답이 달라져요. 순서는 상관없어요!

| 축 | 스스로 물어볼 말 | 😐 붙이기 전 ➡️ 😄 한 겹 붙인 후 |
| --- | --- | --- |
| ❓ **왜** | 이걸 **왜** 하려고? | "급식 앱 만들어줘" ➡️ "알레르기 친구가 급식표 보기 **불편해서**" |
| 📍 **맥락** | **누가, 어디서** 쓰나? | "알림 보내줘" ➡️ "민지는 **등굣길에** 폰을 10초밖에 못 봐" |
| 🧱 **제약** | 뭘 **쓸 수 있고** 못 쓰나? | "제일 좋은 방법으로" ➡️ "**서버 없이, 크롬북으로**" |
| 📏 **기준** | 뭐가 되면 **성공**? | "편한 앱으로" ➡️ "**3초 안에** 알면 성공" |
| ⚖ **검증** | **어떻게 확인**하지? | "이러면 되지?" ➡️ "친구 **5명** 시간 재기" |
| ✂️ **버릴 것** | 일부러 **안 할** 건? | "다 넣어줘" ➡️ "신청 기능은 **이번엔 빼기**" |

> 💡 앱에서 `🧱 제약` 칩을 누르면 → "급식 앱 만들고 싶어. **내가 쓸 수 있는 건 ___ 뿐이야.**"

# 🪜 질문이 자라는 계단 — 빵집 예시

```
                                         4층 ✂️ +버릴 것
                                         "손님용 화면은 이번엔 안 만들어"
                                         → 만들 것 하나가 또렷해짐 🎯
                              3층 📏 +기준
                              "버리는 빵 하루 10개 → 3개면 성공"
                              → 성공했는지 셀 수 있음 📊
                   2층 🧱 +제약
                   "서버 없이, 사장님 폰 하나로"
                   → 진짜 해 볼 수 있는 방법만 남음 ✅
        1층 ❓ +왜
        "빵을 덜 버리고 싶어"
        → 알림 말고 예약·마감 할인도 나옴 💡
 0층 "남은 빵 알림 만들어줘"
```

### 왜 넓혀야 할까? 이유는 딱 두 개!

1. **🔍 내가 아는 것이 드러나요** — 못 채우는 칸 = 아직 모르는 부분
2. **💪 아이디어가 단단해져요** — 발표에서 질문받아도 흔들리지 않아요

# ④ 🧭 화이트보드 테스트 — 4개의 관문

질문을 **2번** 할 때마다 코치가 **퀴즈 카드**를 내요. (5초~30초면 끝!)

```
 🔲 1관문      🎯 2관문      ⚡ 3관문       💥 4관문
 순서도   ──▶   핵심    ──▶   차별점   ──▶   실패 조건  ──▶  🏆 🧩 4/4
```

| 관문 | 코치의 퀴즈 예시 |
| --- | --- |
| 🔲 **순서도** | "화면 닫고, 알림이 울리기까지 순서를 세 칸으로 말해 봐" |
| 🎯 **핵심** | "규칙에서 **한 줄만** 남긴다면 어느 줄이야?" |
| ⚡ **차별점** | "학교 홈페이지 급식표랑 뭐가 달라?" |
| 💥 **실패 조건** | "알레르기 정보가 **비어 있으면** 뭐가 떠야 해?" |

# 👩‍🏫 선생님 대신 앱이 묻는다 — 스마트 화분

| 관문 | 👩‍🏫 선생님이라면 | 🧭 틴스파크AI는 | ✅ 알 수 있는 것 |
| --- | --- | --- | --- |
| 🔲 순서도 | "순서도를 그려 보세요" | "센서값 380이 들어왔어. 어느 상자를 지나가?" | 구조를 **머릿속에** 갖고 있다 |
| 🎯 핵심 | "핵심에 동그라미!" | "한 줄만 남긴다면 어느 줄이야?" | **뭐가 중요한지** 안다 |
| ⚡ 차별점 | "고치기 전엔 어땠어요?" | "타이머로 3초 주는 것과 뭐가 달라?" | 다른 방법과 **비교해서** 골랐다 |
| 💥 실패 조건 | "언제 안 돌아가요?" | "센서가 빠져서 0이 되면?" | **전체를** 볼 줄 안다 |

> 🏅 **안 돌아가는 경우를 아는 사람 = 진짜 만든 사람!**

# 🆘 막혔을 때 — 도움은 3단계로

모르면 한 칸씩 도움을 받아요. **"모르겠어"라고 해도 괜찮아요!**

```
  1단계 💡 힌트         "민지가 아침에 제일 바쁜 순간은 언제일까?"
     │
     ▼
  2단계 📎 예시         "예를 들면… 등굣길 버스 안?"
     │
     ▼
  3단계 🤖 코치의 생각   "나라면 '교실 들어가기 전 10초'로 정할래"
     │
     ▼
  ⏭ 그래도 어려우면    [나중에] → 🧺 복기함에 보관
```

| 이런 순간 | 코치의 반응 |

# 🌟 틴스파크AI만의 특별한 점 TOP 6

1. **🙋 답은 끝까지 + 질문은 하나** — 답도 주고 생각도 키워요
2. **🎚 질문 볼륨 O1~O5** — 가운데(O3)로 가도록 도와줘요
3. **🧩 여섯 축 칩** — 누르면 내 문장에 빈칸이 붙어요
4. **🧭 2번 묻고 1번 퀴즈** — 선생님 대신 자동으로 점검해요
5. **📄 대화가 곧 문서** — 수업이 끝나면 .md 파일 4장 완성!
6. **🫵 내가 정한 것 / 📌 AI가 정한 것** — 구분해서 정직하게 기록해요

> 🔐 **내 기록은 내 것!** 가입 없이 내 기기에 저장돼요. 감시가 아니라 코칭이에요.

# 🛠 오늘의 실습 — 설계도 따라 만들기

> 🎯 **목표:** 버튼을 누르면 화면이 바뀌고, 칩을 누르면 문장이 채워지면 성공!
> (진짜 AI 대신 **미리 적어 둔 가짜 대답**을 써요)

```
STEP 0~1 🟢 준비 · 공통 디자인
    │
    ▼
STEP 2~4 🟢 첫 화면 → 이름 입력 → 형식 고르기
    │
    ▼
STEP 5 ⭐ 🟡 대화 화면 + 💡 자동 완성 + 여섯 축 칩
    │
    ▼
STEP 6~8 🔴 가짜 코치 → 🧭 퀴즈 카드 → 📊 리포트
    │
    ▼
STEP 9 🟡 📄 기획서 보기 · ⬇️ .md 내려받기
```

### Claude에게 요청하는 4단계 공식

**① 설계서 읽히기 → ② 차이점 찾기 → ③ 한 부분만 고치기 → ④ 서연이처럼 써 보기**
