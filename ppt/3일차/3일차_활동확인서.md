| **활동내용** | **① 프론트엔드 + 백엔드 동작 원리 — "웹사이트는 식당이다"**<br>이번 회차는 실습보다 **이론 수업 위주**로 진행하였습니다. 먼저 웹서비스의 구조를 식당에 빗대어 **프론트엔드(홀), 서버·백엔드(주방), 데이터베이스(냉장고), API(웨이터)** 로 나누어 설명하였습니다. 손님이 버튼 하나를 눌렀을 때 주문이 홀에서 주방과 냉장고를 거쳐 다시 화면으로 돌아오는 과정을 따라가며, **눈에 보이는 화면 뒤에서 어떤 일이 일어나는지**를 살펴보았습니다.<br><br>**② 바이브 코딩 개발 과정 — "말로 지휘해서 만든다"**<br>바이브 코딩을 AI에게 **말하고 → 결과를 보고 → 다듬는** 과정의 반복으로 설명하고, 사람은 무엇을·왜·누구를 위해 만들지 정하는 **지휘자**, AI는 코드를 쓰는 **연주자**라는 역할 구분을 다루었습니다. 이어 v0(화면 제작) → GitHub(코드 보관) → 코딩 에이전트(기능 개선) → Vercel(배포) → CI/CD(자동 검사·배포)로 이어지는 실제 개발 흐름을 한 장의 지도로 정리하여, 각 도구가 **어떤 순서로, 왜 필요한지**를 설명하였습니다.<br><br>**③ 프론트엔드 완성품 분석 — 왜 이렇게 개발하고, 왜 프론트엔드부터 만드는가**<br>프론트엔드로 개발한 완성품을 함께 살펴보며, 서버와 실제 AI 호출 없이 **미리 준비한 데이터와 규칙만으로 서비스처럼 동작**하는 구조를 분석하였습니다. 이를 바탕으로 ▲사용자는 서버가 아니라 화면을 먼저 만나고 ▲화면으로 먼저 검증하면 버릴 서버를 만들지 않으며 ▲검증 과정에서 다듬어진 데이터 구조가 나중에 데이터베이스 설계도가 된다는 점을 들어, **프론트엔드부터 개발하는 이유**를 설명하였습니다. 또한 화면과 데이터의 연결 지점을 나누어 두면 뒤에 진짜 서버와 AI로 교체할 때도 화면을 크게 고치지 않아도 된다는 점을 다루었습니다. |
